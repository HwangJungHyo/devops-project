# Architecture Decision Records (ADR)

기술적 결정과 그 이유를 기록한다. 목적은 결정 자체가 아니라
**그때 알던 정보와 판단 근거**를 남기는 것이다. 면접에서 "왜 그렇게
만들었는가"에 대한 답변의 원본이다.

## 언제 쓰는가

- 되돌리는 데 비용이 드는 결정 (플랫폼, 데이터 저장소, 레포 구조)
- 선택지가 둘 이상이었고 하나를 골라야 했던 경우

쓰지 않는 것: 되돌리기 쉬운 결정, 선택의 여지가 없었던 것.

**결정하기 전 또는 결정하는 시점에 쓴다.** 끝난 뒤에 쓰면 정당화 글이 된다.

## 규칙

- 파일명: `NNNN-짧은-제목.md`, 번호는 4자리 순차 증가, 재사용 금지
- 기존 ADR은 수정하지 않는다. 결정이 바뀌면 새 ADR을 쓰고
  이전 것의 상태만 `Superseded by ADR-NNNN`으로 바꾼다
- 초안은 사용자가 쓴다. Claude는 첨삭·반박만 (COLLABORATION.md)
