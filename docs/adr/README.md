# Architecture Decision Records (ADR)

이 디렉토리는 이 프로젝트에서 내린 기술적 결정과 그 이유를 기록한다.

## 왜 쓰는가

6개월 뒤에 "왜 EKS가 아니라 ECS였지?"라는 질문을 받았을 때, 기억이 아니라 문서로 답하기 위해서다. 결정 자체보다 **그때 알던 정보와 판단 근거**를 남기는 것이 목적이다.

이 프로젝트의 최종 평가 기준은 무엇을 만들었는가가 아니라 **왜 그렇게 만들었는지 설명할 수 있는가**다. 이 디렉토리가 그 답변의 원본이다.

## 언제 쓰는가

다음에 해당하면 ADR을 쓴다.

- 되돌리는 데 비용이 드는 결정 (플랫폼, 데이터 저장소, 레포 구조)
- 선택지가 둘 이상이었고 그중 하나를 골라야 했던 경우
- 나중에 "왜 이렇게 했지?"라는 질문이 나올 것 같은 경우

쓰지 않아도 되는 것: 되돌리기 쉬운 결정, 관례를 그대로 따른 것, 선택의 여지가 없었던 것.

## 언제 쓰는가 (시점)

**결정하기 전 또는 결정하는 시점에 쓴다.** 작업이 끝난 뒤에 쓰면 결과를 정당화하는 글이 되고, 기각한 대안의 근거가 흐려진다.

## 규칙

- 파일명: `NNNN-짧은-제목.md` (예: `0001-deployment-platform.md`)
- 번호는 4자리, 순차 증가. 한 번 부여한 번호는 재사용하지 않는다
- **기존 ADR을 수정하지 않는다.** 결정이 바뀌면 새 ADR을 쓰고, 이전 ADR의 상태를 `Superseded by ADR-NNNN`으로만 바꾼다
- 템플릿: [`template.md`](./template.md)

## 상태 값

| 상태 | 의미 |
|---|---|
| `Proposed` | 검토 중, 아직 확정 아님 |
| `Accepted` | 확정, 현재 유효 |
| `Superseded by ADR-NNNN` | 다른 결정으로 대체됨 |
| `Deprecated` | 더 이상 유효하지 않으나 대체 결정 없음 |
