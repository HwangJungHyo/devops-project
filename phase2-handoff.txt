[4. 멘토 피드백 요점 (상세: docs/notes/2026-08-17-phase2-mentor-notes.md)]
- ADR은 더 짧아도 됨. 양보다 "왜, 어디에 포인트"의 설명력
- 서브넷 타이트하게: 퍼블릭 /26~/28로 좁게, 프라이빗 넉넉히
  (VPC CNI가 Pod마다 실 IP 소모 → 프라이빗이 IP를 많이 먹음)
- 엔터프라이즈는 네트워크 계정과 EKS 계정 분리 (계정 경계 = 조직 경계)
- IAM: User 금지, 전부 Role + AssumeRole, 최소 권한, admin 금지, IRSA
- 노드 접근은 SSH 아닌 SSM 경유
- 노드 오토스케일링: Karpenter vs Cluster Autoscaler (Phase 9에서 결정)
- Makefile 퀵런치(make init/make run)는 보류된 백로그 (Phase 1 꼬리)

[5. 진행 순서 (합의됨)]
1) EKS/K8s 기초 학습 — EKS 브리핑은 이미 제공됨 (컨트롤 플레인 매니지드,
   데이터 플레인=EC2 노드, VPC CNI의 IP 소모, IRSA, 오토스케일링 2층).
   사용자가 EKS 공식 문서 + K8s 기본 오브젝트 학습 중
2) 멘토 과제 1: 엔터프라이즈 AWS Organizations/OU 설계 문서
   → docs/design/org-structure.md. AWS multi-account strategy 백서 기반.
   각 OU/계정에 담당 조직 명시. 완성되면 Claude가 반박 리뷰
3) 멘토 과제 2+3: 단순화 네트워크 구조 + 아키텍처 다이어그램
   (VPC, 퍼블릭/프라이빗 서브넷, EKS, IAM Role — Terraform 작성 전 필수)
4) 인프라 레포 생성 + ADR-0002(EKS)·0003(IaC 도구)·0004(state 저장/잠금)
   → 이후 Terraform 구현 시작
